# Тестовое задание

Приложение получает сделки через workflow n8n и отображает их в динамической HTML-таблице.

## Структура проекта

```text
├── php/
│   └── index.php
├── n8n/
│   └── workflow.json
└── README.md
```

## Архитектура

```text
PHP → GET webhook n8n → получение списка ID
                         → получение сделки по каждому ID
                         → подготовка итогового JSON
PHP ← success/total/data/errors
```

PHP выполняет один GET-запрос к n8n. Workflow получает список ID сделок, запрашивает данные каждой сделки и возвращает готовый список для таблицы.

## Формат ответа n8n

```json
{
  "success": true,
  "total": 10,
  "data": [
    {
      "id": 1001,
      "title": "Сделка с ООО Ромашка",
      "amount": 1250000,
      "responsible": {
        "id": 12,
        "name": "Иван Петров"
      },
      "company": {
        "id": 78,
        "name": "ООО Ромашка"
    }
  "errors": []
}
```

Если одна из сделок не загрузилась, остальные данные всё равно возвращаются:

```json
{
  "success": false,
  "total": 1,
  "data": [
    {
      "id": 1001,
      "title": "Сделка с ООО Ромашка",
      "amount": 1250000,
      "responsible": {
        "id": 12,
        "name": "Иван Петров"
      },
      "company": {
        "id": 78,
        "name": "ООО Ромашка"
      }
    }
  ],
  "errors": [
    {
      "id": 999999,
      "message": "Сделка с ID 999999 не найдена"
    }
  ]
}
```

## Обработка ошибок

В запросе отдельной сделки включена настройка `Never Error`. Благодаря этому ошибка одного ID не останавливает весь workflow.

Успешные сделки помещаются в `data`, а ошибки отдельных запросов — в `errors`. Поле `total` содержит количество успешно загруженных сделок.

PHP дополнительно проверяет:

- ошибку подключения к n8n;
- HTTP-статус ответа;
- корректность JSON;
- наличие массива `data`.

Все значения перед выводом экранируются через `htmlspecialchars`.

## Запуск workflow

1. Импортировать `n8n/workflow.json` в n8n.
2. Опубликовать или активировать workflow.
3. Скопировать Production URL узла Webhook.
4. Указать этот URL в переменной `$n8nUrl` файла `php/index.php`.

Путь webhook:

```text
/webhook/api/test.task/get.deals
```

## Запуск PHP

Требования:

- PHP 8.0 или новее;
- расширение cURL.

Из корня проекта выполнить:

```bash
php -S localhost:8000 -t php
```

После запуска открыть:

```text
http://localhost:8000
```

## Использованные технологии

- n8n;
- PHP без фреймворков;
- Bootstrap 5;
- внешний REST API.

## Принятые решения и допущения

- Для колонки «Сумма» используется поле `amount`. Исходный API также содержит `opportunity`, но в ТЗ не уточняется, какое из двух значений требуется.
- n8n возвращает только пять полей, необходимых таблице. Остальные поля исходной сделки не передаются PHP.
- Ошибка отдельного ID не приводит к потере остальных сделок.
- Авторизация, база данных, пагинация и повторные запросы не добавлялись, поскольку они не требуются в ТЗ.
- Bootstrap загружается через CDN и используется только для оформления страницы.
